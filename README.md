# 風雅存製作團隊 LINE 官方帳號

團隊成員透過 LINE 官方帳號查看自己的工作與進度，不需要直接操作 Notion，也就不會誤刪 Notion 的欄位或資料。架構沿用苗栗收容所系統與 line-namecard 會員模組：**LINE 官方帳號＋LIFF（GitHub Pages）＋Make.com＋Notion**。

## 使用流程

```
加好友 ──► 訪客選單［加入團隊成員］──填姓名與角色──► 審核中
                                              │
          製作人或導演在［核准團隊成員］確認角色 ◄──┘（LINE 推播通知）
                                              │
     ┌────────────────────────────────────────┴──────────────────┐
編劇、藝術總監、作畫監督、聲音總監                             製作人、導演
團隊成員選單［我的工作］［我的進度］                  製作人／導演選單［核准團隊成員］［團隊進度］
```

| 畫面 | 網址參數 | 誰能用 | 內容 |
|---|---|---|---|
| 加入團隊成員 | `?v=join` | 所有人 | 填真實姓名、選角色、補充說明；審核中可修改 |
| 我的工作 | `?v=work` | 團隊成員 | 退回修改、已逾期、本週到期、之後的工作；`&f=` 帶篩選時只列符合的工作 |
| 我的進度 | `?v=progress` | 團隊成員 | 完成率、各階段進度、依狀態分組的任務。數字都可以點：點了到「我的工作」只列那些工作（`f=status:待審核`、`stage:2 前期製作`、`overdue`、`thisWeek`） |
| 核准團隊成員 | `?v=approve` | 製作人、導演 | 待核准名單，確認角色後核准或退回 |
| 團隊進度 | `?v=team` | 製作人、導演 | 版面同「我的進度」，可切換全部或單一角色；最上面列出待審核的工作 |
| 工作項目 | `?v=task&id=` | 負責的成員、製作人、導演 | 點清單裡任一項工作進入。「目前進度」一句話說明輪到誰；送審時並排「上一版的審核意見」和「這一版的說明」。交付檔案顯示雲端硬碟縮圖。負責的成員可交件（見下）；製作人、導演在「待審核」時可核准或退回（退回要寫意見）；「修改歷程」依版本分組列出每次送審、退回、核准 |

交件時可以改狀態（只能選尚未開始、執行創作中、待審核，不能自己核准）、雲端硬碟連結、留言，並上傳一個檔案。時間與版本號一律由系統寫入，成員不用填：提交時間、實際交付日在送審當下寫入，審核日期在核准或退回當下寫入；版本號在每次送審時自動加一（第一次送審沿用 Notion 上已有的版本，沒有就是 V1；待審核期間重新儲存不跳號；「最終定案」不再變動）。照片會在手機上先縮成 1600px；其他檔案 3MB 以內，大檔請放雲端硬碟貼連結。上傳的檔案存到 Google 雲端硬碟的「風雅存交件」資料夾，Notion「交付檔案上傳」放的是雲端硬碟連結。這一版**不主動推播**（推播會扣 LINE 官方帳號每月免費訊息額度，團隊人數少，成員習慣自己打開頁面看狀態）：待審核的工作列在「團隊進度」最上面，退回的工作列在成員「我的工作」最上面。要恢復推播時，把 `tools/config.local.json` 的 `line.push` 改成 `true` 再重新產生藍圖，就會在新申請、申請結果、送審、審核結果時通知。每次交件、審核都會在「📝 審核紀錄」新增一筆，記下身分與姓名。

**返回上一頁**：LIFF 沒有瀏覽器的上一頁鍵，按右上角 ✕ 會關掉整個頁面。所以每往下一層（點工作、點數字篩選、前往我的工作）都在瀏覽紀錄記一筆，左上角「‹ 返回」和手機的返回鍵都回到上一個畫面；從 LINE 選單直接打開的第一頁不顯示返回。直接用網址打開工作項目或篩選清單時，返回會回到該角色的首頁（成員：我的工作；製作人、導演：團隊進度）。

導演與製作人目前用同一套畫面，但 LINE 上是兩張選單（別名 `producer`、`director`），之後要分開調整時改 `tools/make_richmenu.py` 與 `tools/make_blueprints.py` 的 `MENUS` 即可。

## 權限與資料範圍

- 每次請求都先向 LINE 驗證 Access Token 屬於本系統的 LINE Login channel，再用 userId 查名冊。
- 總監只會拿到自己角色的任務；導演與製作人拿到全部任務。這個篩選在 Make 端做，不靠頁面。
- 核准、退回、待核准名單只開放給 `roles.json` 的 `approvers`（製作人、導演），也是在 Make 端檢查。
- 總監只能打開、修改自己職掌的任務；已核准的任務不能再改。審核只開放給製作人、導演，而且任務必須是「待審核」。這些檢查都在 Make 端。
- Make 只會**更新**「📋 製作流程查核總表」的這些欄位：狀態、版本號、交付雲端連結、交付檔案上傳、執行者留言、提交人、提交時間、實際交付日、審核意見、審核日期、審核身分、審核人。沒有任何刪除模組；任務名稱、日期、職掌等其他欄位都不會動。
- 會新增資料的只有「👥 LINE 團隊成員」名冊和「📝 審核紀錄」。

## 本機預覽

```bash
python -m http.server 5192 --directory liff/app
```

打開 `http://localhost:5192/?as=製作人`。`as` 可以換成 `guest`、`pending`、`rejected` 或六個角色之一，`v` 指定畫面。本機用的是 `mock-data.js` 的 Notion 快照，狀態與日期是虛構的。交件、審核只改瀏覽器記憶體裡的資料，重新整理就還原。

## Make 的地雷（沿用苗栗與 line-namecard 的經驗）

- 用 API 建立的 HTTP 模組要補上預設值（`HTTP_DEFAULTS`），否則請求不會送出。
- HTTP 模組遇到 4xx 會中斷整個執行；錯誤處理路線要放 Webhook response＋Ignore，頁面才收得到錯誤。
- Router 一定是路線的最後一個模組，後面接的模組不會執行。
- 匯入 webhook 觸發的情境後，確認排程仍是「Immediately」；**重新匯入到既有情境也會被重設成每 15 分鐘**（2026-10-22 LIFF API 發生過），頁面只收到「Accepted」。手動執行的情境同樣要改回「On demand」。
- 模組放進 router 之後才設定的篩選不會進藍圖（router 會複製模組）。2026-10-22「刪除舊選單」的篩選因此沒生效，把新建的四張選單也刪了。
- Notion「Search Objects」的查詢條件不會計算 `{{ }}` 運算式；而且 Notion 遇到不存在的單選選項會回 400。依角色篩任務改在彙整時做（`to_json` 的 `keep`）。
- 「Make an API Call」遇到 4xx 不一定會中斷，執行紀錄仍顯示成功；要確認結果時看執行紀錄裡每個模組的輸出，不要只看 SUCCESS。
- 「Create a Rich Menu」勾了 selected 會把剛建好的那張設成預設，所以「設為預設選單」放在四張都建完之後。
- 只偶爾手動執行的情境（建立圖文選單）排程設成「On demand」並保持開啟。
- Notion 欄位一改名，Make 就讀不到。名冊建好後請鎖定資料庫。
