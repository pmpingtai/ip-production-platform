# 部署說明

照順序做完，就能在自己的帳號架起整套系統。測試期間放在朕宏的帳號（Make：G_purchase），交付時照同樣步驟在風雅存的帳號再做一次，或依 [交接清單](交接清單.md) 轉移。

## 1. Notion

已建好的部分（2026-10-21）：

- 「🎬 風雅存製作平台」底下新增「📱 LINE 官方帳號｜團隊成員與選單」頁，裡面是「👥 LINE 團隊成員」名冊。
- 任務與專案沿用既有的「📋 製作流程查核總表」「📁 風雅存_專案資料庫（進行中＋歷年）」。

要做的事：

1. 「👥 LINE 團隊成員」右上角「⋯」→「鎖定資料庫」。Make 依欄位名稱讀寫，欄位改名後 LINE 上的功能會失效。鎖定後仍可以編輯資料列，Make 的寫入也不受影響。
2. 三張表的 data source ID 填進 `tools/config.local.json` 的 `notion`（已填好）。
3. 「📋 製作流程查核總表」用到的欄位：任務名稱、序號、階段、工作流程、查核點、執行職掌、狀態、預計交付日、版本號、所屬專案、範本任務、交付雲端連結、交付檔案上傳、執行者留言、提交人、提交時間、實際交付日、審核意見、審核日期、審核身分、審核人。這些欄位改名前，要先同步修改 `liff/app/app.js`、`liff/app/stats.js` 與 `tools/make_blueprints.py`。
4. 「📝 審核紀錄」（2026-10-22 建立，和任務表雙向關聯）：data source ID 填 `notion.reviews_ds`，database ID 填 `notion.reviews_db`（查詢紀錄用的是舊版 database API）。建好後同樣鎖定資料庫。

## 2. LINE

1. 建立新的 LINE 官方帳號，到 LINE Developers 開啟 Messaging API（Provider 建議命名「風雅存」）。
2. 「Messaging API」分頁：關閉「自動回應訊息」，開啟「Webhook」（網址在第 3 步取得）。
3. 在**同一個 Provider** 底下建立 **LINE Login channel**，新增 LIFF app：
   - Size：Full
   - Endpoint URL：`https://<GitHub 帳號>.github.io/<repo>/liff/app/`
   - Scope：`openid`、`profile`
   - Bot link feature：On (Aggressive)，讓使用者開 LIFF 時順便加官方帳號好友
4. LINE Login channel 的狀態改成 **Published**（Developing 狀態只有開發者自己能登入）。
5. 記下 LIFF ID 和 LINE Login 的 Channel ID，填進 `tools/config.local.json` 的 `line`，並把 `liff/app/app.js` 開頭 `CONFIG.liffId` 換成 LIFF ID。

## 3. Make.com（G_purchase）

1. 建立資料夾「風雅存」，並新增同名標籤（和「苗栗」「朕宏」分開）。資料夾編號填進 `make.folder_id`。
2. 建立連線：
   - **風雅存 Notion**：Notion（OAuth）。授權畫面只勾「🎬 風雅存製作平台」頁（底下的三張表會一起授權）。
   - **風雅存 LINE**：LINE，填 Messaging API 的 Channel access token（long-lived）。
   - **風雅存 Google 雲端硬碟**：Google Drive（OAuth），用專案 Gmail 登入。
   - 三個連線的編號填進 `make.notion_connection_id`、`make.line_connection_id`、`make.drive_connection_id`。
   - 在專案 Gmail 的雲端硬碟建立資料夾「風雅存交件」，共用設定改成「知道連結的任何人：檢視者」（導演、製作人才打得開交件檔案）。資料夾網址最後一段 ID 填進 `make.drive_folder_id`。
3. 建立兩個 webhook：
   - Custom webhook「風雅存 LIFF API」：編號填進 `make.api_hook_id`；網址填進 `liff/app/app.js` 的 `CONFIG.apiUrl`。
   - LINE「Watch Events」webhook「風雅存 LINE 事件」：編號填進 `make.events_hook_id`；網址貼到 LINE Developers 的 Webhook URL，按 Verify。
4. 產生藍圖：

   ```bash
   python tools/make_blueprints.py
   ```

5. 依序匯入 `make/` 的三份藍圖（Create a new scenario →「⋯」→ Import Blueprint），放進「風雅存」資料夾：
   - 「風雅存｜建立圖文選單（手動執行）」：排程設 On demand，保持開啟。**要等第 4 節頁面上線後**才執行。
   - 「風雅存｜LINE 事件」：啟用。
   - 「風雅存｜LIFF API」：啟用，確認排程是 Immediately。
   - 之後修改產生器、重新匯入到既有情境時，排程會被重設，每次都要重新確認。

## 4. GitHub Pages

1. 建立 repo（建議放在專案帳號，之後一起移交），推上整個資料夾。`tools/config.local.json` 與 `make/*.blueprint.json` 已列在 `.gitignore`，不會推上去。
2. Settings → Pages → Source 選 `main` 分支、根目錄。
3. 確認 `https://<帳號>.github.io/<repo>/assets/richmenu_guest.png` 打得開，再把網址填進 `pages_base`、`page_origin`，重新產生藍圖並更新 Make 情境。
4. `liff/app/index.html` 的 CSP 只允許連到 `hook.us2.make.com`；Make 帳號換區域時要一起改。

## 5. 上線測試

1. 到 Make 手動執行一次「風雅存｜建立圖文選單（手動執行）」。
2. 用手機加官方帳號好友，下方應出現「加入團隊成員」選單；Notion 名冊會多一筆「訪客」。
3. 第一位製作人：先自己申請，再到 Notion 名冊把自己的「狀態」改成「已核准」、「角色」改成「製作人」，然後重新打開 LIFF（打開時會自動校正選單）。之後的成員都由製作人在 LINE 上核准。
4. 用另一支手機申請「藝術總監」，製作人打開「核准團隊成員」應看到這筆申請（`line.push` 為 true 時也會收到推播）；核准後對方選單換成團隊成員版，「我的工作」看得到藝術總監的任務。

## 操作量估算

每次打開「我的工作」「我的進度」「團隊進度」約 8 個 operations（驗證 2、名冊 1、任務 1＋彙整 2、專案 1＋彙整 2）。6 人每人每天打開 3 次、每月 22 個工作天，約 3,200 個 operations；G_purchase 的 Core 方案每月 10,000 個，與苗栗、朕宏共用。
