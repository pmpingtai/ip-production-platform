# 交接清單

本系統由「Notion＋Make.com＋LINE 官方帳號＋GitHub Pages」組成。測試期間放在朕宏的帳號，驗收後整套移交給風雅存。

> 這份文件**不放任何帳號密碼或金鑰**。登入資訊另外交接。

## 一、帳號與服務

| 項目 | 用途 | 測試期間 | 移交方式 |
|---|---|---|---|
| LINE 官方帳號 | 團隊成員的介面 | 朕宏新建（風雅存專用） | 在 LINE Official Account Manager 把風雅存的管理者設為「管理員」，再移除朕宏 |
| LINE Developers Provider | Messaging API、LINE Login、LIFF | 朕宏帳號 | 把風雅存加為 Provider Admin，再移除朕宏 |
| Make.com | 三個情境 | G_purchase 的「風雅存」資料夾 | 在風雅存的 Make 帳號重新匯入藍圖（見第二節） |
| Notion | 名冊與任務資料 | 風雅存的工作空間（已在正式位置） | 不用搬；只要換 Make 的 Notion 連線 |
| GitHub | LIFF 頁面與選單圖片 | 專案帳號 | 轉移 repo 擁有權（Settings → Transfer），網址會改變 |

## 二、Make 換帳號

1. 在新帳號建立「風雅存 Notion」「風雅存 LINE」連線，以及兩個 webhook（步驟同 [部署說明](部署說明.md) 第 3 節）。
2. 在 `tools/config.local.json` 換成新的編號，執行 `python tools/make_blueprints.py`，匯入三份藍圖並啟用。
3. LIFF 頁面的 `CONFIG.apiUrl` 換成新的 webhook 網址，推上 GitHub。
4. LINE Developers 的 Webhook URL 換成新的「LINE 事件」webhook 網址。
5. 確認新帳號運作正常後，停用並刪除 G_purchase 裡的「風雅存」情境與連線。

## 三、GitHub repo 換網址後

1. LIFF app 的 Endpoint URL 換成新網址。
2. `pages_base`、`page_origin` 換成新網址，重新產生藍圖並更新 Make 情境（建立圖文選單會從這裡下載圖片；LIFF API 的 CORS 也用它）。
3. 執行一次「風雅存｜建立圖文選單（手動執行）」。

## 四、日常維運

| 要做的事 | 在哪裡做 |
|---|---|
| 核准新成員、決定角色 | LINE「核准團隊成員」 |
| 停用某位成員 | Notion 名冊把「狀態」改成「停用」；對方下次打開 LIFF 時選單會自動換回訪客版 |
| 改某位成員的角色 | Notion 名冊改「角色」；對方下次打開 LIFF 時選單會自動校正 |
| 換選單圖片 | 改 `tools/make_richmenu.py` → 執行 → 推上 GitHub → 手動執行「建立圖文選單」 |
| Notion 執行職掌整理完畢 | 把 `liff/app/roles.json` 的 `aliases` 縮減成只留同名角色，重新產生藍圖並更新「LIFF API」 |
| 新增角色 | 改 `roles.json`、Notion 名冊的「角色」「申請角色」選項，重新產生藍圖 |
